## 长期记忆更新

### n8n + MiniMax + Ollama 三层架构正式通车

历经 Node.js 版本降级、SQLite 重建、端口代理等层层排查，本地 AI 工具生态三层架构全链路打通：

- **LLM 推理层**: Ollama（端口 11434，代理 11435）
- **AI 代理/编排层**: DeerFlow（端口 2026）
- **工作流自动化层**: n8n（端口 5678）

### 关键协议转换代理部署

| 代理端口 | 用途 | 解决问题 |
|---------|------|---------|
| 11435 | Ollama 代理 | 日志记录 + 连接稳定性 |
| 11436 | MiniMax 代理 | /v1/responses → /v1/chat/completions 格式转换 |

核心壁垒确认：n8n/LangChain JS SDK 6.x 发送 OpenAI Responses API 格式（/v1/responses），MiniMax 仅支持 Chat Completions API（/v1/chat/completions），导致 Title Generation 返回 404 MODEL_NOT_FOUND。端口 11436 代理完成协议适配后问题根除。

## 优化与改变

### 技术调试方法论沉淀

- **Node.js 兼容性**: v24 与 sqlite3 预编译二进制不兼容，降级至 v20.18.0 LTS 解决
- **数据库 Schema 不兼容**: n8n 升级后旧 database.sqlite 缺少新字段，删库重建
- **API 协议不匹配**: LangChain SDK 与 MiniMax API 格式差异，通过代理层转换适配
- **安装策略**: MSI 静默安装失败后果断切换解压 zip 法，体现"此路不通就换条路"的务实风格

首个实际需求明确：Word 文档智能配图工作流
