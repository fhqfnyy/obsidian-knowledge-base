# 人脑式认知智能体总体框架

## 一、项目目标

本项目旨在构建一个具备长期记忆、持续人格、目标驱动、自主思考、经验积累和自我修正能力的智能体。

该智能体不依赖无限大的上下文窗口，而是模拟人脑的基本认知机制：

- 当前只保留有限的工作记忆；
    
- 将大量历史信息存入长期记忆；
    
- 根据当前问题主动唤醒相关记忆；
    
- 在思考过程中反复检索、验证和修正；
    
- 将新经历转化为稳定知识；
    
- 对不重要的信息逐渐降低记忆权重；
    
- 长期维持相对一致的自我、人格、价值观和目标。
    

系统的核心不是“把所有内容一次性发送给大模型”，而是建立：

[  
\text{有限工作空间}  
+  
\text{长期记忆系统}  
+  
\text{动态检索机制}  
+  
\text{目标与价值系统}  
+  
\text{元认知控制}  
]

# 二、总体架构

系统可以划分为九个核心层级：

```text
外部环境与用户输入
        ↓
感知与输入理解层
        ↓
全局工作空间
        ↕
认知控制器
        ↕
推理与规划引擎
        ↕
记忆管理系统
        ↕
目标、价值与情绪系统
        ↕
自我模型与世界模型
        ↓
行动执行层
        ↓
结果反馈与学习
```

核心模块包括：

1. 感知与输入理解层；
    
2. 全局工作空间；
    
3. 认知控制器；
    
4. 推理与规划引擎；
    
5. 长期记忆系统；
    
6. 目标与价值系统；
    
7. 自我模型；
    
8. 世界模型；
    
9. 行动、反馈与学习系统。

# 三、感知与输入理解层

## 3.1 模块作用

感知层负责接收智能体面对的各种输入，并将其转化为统一的内部事件。

输入类型可以包括：

- 用户文本；
    
- 语音；
    
- 图像；
    
- 视频；
    
- 文件；
    
- 数据库记录；
    
- 软件界面状态；
    
- 传感器信息；
    
- 外部系统通知；
    
- 智能体自身的行动结果。
    

## 3.2 统一事件结构

所有输入建议转化为统一事件对象：

```json
{
  "event_id": "evt_20260713_0001",
  "event_type": "user_message",
  "timestamp": "2026-07-13T15:45:00+01:00",
  "source": "user",
  "content": "帮我设计一个人脑式智能体",
  "entities": [
    "人脑模型",
    "智能体",
    "长期记忆"
  ],
  "intent": "architecture_design",
  "importance": 0.82,
  "emotional_tone": "positive",
  "confidence": 0.96
}
```

这样可以避免不同输入来源分别建立一套处理逻辑。

## 3.3 输入预处理

感知层需要完成：

- 语言识别；
    
- 意图识别；
    
- 实体提取；
    
- 时间解析；
    
- 情绪识别；
    
- 任务分类；
    
- 风险识别；
    
- 信息重要性初步评估；
    
- 与已有项目、人物和记忆建立关联。

# 四、全局工作空间

## 4.1 定义

全局工作空间相当于智能体当前的“意识区域”。

它不是全部记忆，而是当前被激活、正在参与思考的信息集合。

工作空间应包含：

```text
当前用户输入
当前任务目标
最近完整对话
当前计划
已激活的相关记忆
当前假设
待验证问题
工具执行结果
风险与约束
当前自我状态
```

## 4.2 工作空间容量

建议设置硬性容量限制，例如：

- 轻量智能体：16K～64K token；
    
- 标准智能体：64K～256K token；
    
- 深度研究智能体：256K～1M token。
    

即使模型支持更长上下文，也不应默认全部使用。

原因是：

- 信息越多，注意力越分散；
    
- 冲突信息越难处理；
    
- 成本和延迟越高；
    
- 推理稳定性可能下降。
    

## 4.3 工作空间状态结构

```json
{
  "current_goal": "设计人脑式智能体架构",
  "active_task": "输出总体技术框架",
  "active_memories": [],
  "current_hypotheses": [],
  "open_questions": [],
  "constraints": [],
  "current_plan": [],
  "tool_results": [],
  "attention_focus": [
    "记忆系统",
    "认知控制",
    "长期学习"
  ]
}
```

## 4.4 工作空间更新原则

每完成一个思考步骤，系统应决定：

- 哪些内容继续保留；
    
- 哪些内容压缩；
    
- 哪些内容写入长期记忆；
    
- 哪些内容暂时退出工作空间；
    
- 下一轮应重新激活哪些记忆。

# 五、认知控制器

## 5.1 核心作用

认知控制器是整个智能体的调度中心，相当于“执行功能”。

它不一定直接负责回答问题，而是负责决定：

- 当前应该思考什么；
    
- 是否需要检索记忆；
    
- 是否需要调用工具；
    
- 是否需要制定计划；
    
- 是否需要反思；
    
- 是否应停止继续推理；
    
- 当前结论是否足够可靠；
    
- 是否需要询问用户；
    
- 当前任务优先级是什么。
    

## 5.2 认知循环

推荐采用循环式认知架构：

```text
观察
↓
理解
↓
确定目标
↓
检索记忆
↓
形成假设
↓
制定计划
↓
执行行动
↓
检查结果
↓
反思与修正
↓
更新记忆
```

可表示为：

[  
O \rightarrow I \rightarrow G \rightarrow R \rightarrow H  
\rightarrow P \rightarrow A \rightarrow E \rightarrow U  
]

其中：

- (O)：Observe，观察；
    
- (I)：Interpret，理解；
    
- (G)：Goal，确定目标；
    
- (R)：Retrieve，检索；
    
- (H)：Hypothesize，形成假设；
    
- (P)：Plan，规划；
    
- (A)：Act，行动；
    
- (E)：Evaluate，评估；
    
- (U)：Update，更新。
    

## 5.3 任务状态机

每项任务建议采用明确状态：

```text
NEW
UNDERSTANDING
RETRIEVING
PLANNING
EXECUTING
VERIFYING
WAITING
COMPLETED
FAILED
SUSPENDED
```

这样可以避免智能体在多任务环境中失去当前进度。

# 六、长期记忆系统

长期记忆是整个人脑式智能体的核心。

建议至少划分为七类记忆。

## 6.1 情景记忆

情景记忆保存具体经历，即“什么时候发生了什么”。

示例：

```json
{
  "memory_type": "episodic",
  "timestamp": "2026-07-13",
  "participants": ["user", "agent"],
  "event": "用户提出建立人脑式智能体",
  "context": "讨论上下文长度与长期记忆",
  "outcome": "决定设计分层记忆架构"
}
```

适用于：

- 对话历史；
    
- 项目事件；
    
- 决策过程；
    
- 工具调用结果；
    
- 成功和失败经历；
    
- 用户反馈。
    

## 6.2 语义记忆

语义记忆保存提炼后的知识和事实。

示例：

```json
{
  "subject": "人脑式智能体",
  "predicate": "需要",
  "object": "分层记忆系统",
  "confidence": 0.94,
  "source": ["episode_1001", "document_320"],
  "valid_from": "2026-07-13"
}
```

语义记忆包括：

- 通用知识；
    
- 用户稳定信息；
    
- 项目参数；
    
- 设备信息；
    
- 技术规则；
    
- 概念关系；
    
- 已确认事实。
    

## 6.3 程序性记忆

程序性记忆保存“如何做”。

例如：

- 如何生成技术报告；
    
- 如何分析故障；
    
- 如何创建项目计划；
    
- 如何调用某个工具；
    
- 如何调试 PLC；
    
- 如何执行代码检查。
    

建议保存形式：

```json
{
  "skill_name": "industrial_fault_analysis",
  "trigger_conditions": [
    "设备故障",
    "用户提供运行参数"
  ],
  "steps": [
    "确认故障现象",
    "提取设备参数",
    "建立可能原因",
    "按概率排序",
    "提出验证方法",
    "生成处理方案"
  ],
  "success_rate": 0.86
}
```

程序性记忆最好逐步转化为可执行工作流、脚本或工具，而不仅是文本。

## 6.4 人物与关系记忆

保存人物、组织和智能体之间的关系。

```json
{
  "entity": "user_001",
  "display_name": "Frank",
  "relationship": "primary_user",
  "profession": "electrical_automation_engineer",
  "preferences": {
    "language": "Chinese",
    "output_style": "technical_and_structured"
  },
  "trust_level": 0.91
}
```

还应保存：

- 人物之间的关系；
    
- 组织架构；
    
- 用户与项目的关系；
    
- 用户与供应商、业主、同事的关系；
    
- 信息由谁提供。
    

## 6.5 目标记忆

保存长期目标、中期目标和当前任务。

```json
{
  "goal_id": "goal_001",
  "goal": "建立具备长期记忆的人脑式智能体",
  "priority": 0.9,
  "status": "active",
  "parent_goal": null,
  "sub_goals": [
    "完成记忆架构",
    "完成认知控制器",
    "完成原型系统"
  ]
}
```

## 6.6 情绪与价值记忆

这一部分不是为了模拟夸张情绪，而是为决策增加稳定偏好。

可以保存：

- 用户满意度；
    
- 某类行为的正负反馈；
    
- 风险敏感程度；
    
- 信任变化；
    
- 任务紧迫程度；
    
- 某段经历的情绪强度。
    

```json
{
  "target": "technical_accuracy",
  "value": 0.95,
  "type": "core_value"
}
```

## 6.7 自我记忆

保存智能体关于自身的稳定认知：

- 名称；
    
- 身份；  
    -能力边界；
    
- 工具权限；
    
- 长期职责；
    
- 已完成任务；
    
- 经历过的关键事件；
    
- 自己曾经犯过的错误；
    
- 自己擅长和不擅长的领域。

# 七、记忆存储架构

不建议只使用向量数据库。

应采用多种数据库组合。

## 7.1 推荐的数据层

### 关系数据库

可使用 PostgreSQL 或 MySQL。

用于保存：

- 用户；
    
- 项目；  
    -任务；  
    -事件；  
    -目标；  
    -参数；  
    -时间；  
    -状态；  
    -版本。
    

### 向量数据库

可使用：

- pgvector；
    
- Qdrant；
    
- Milvus；
    
- Weaviate；
    
- Chroma。
    

用于语义检索：

- 相似经历；
    
- 相似对话；
    
- 文档片段；
    
- 模糊概念；
    
- 相关问题。
    

### 全文搜索引擎

可使用 Elasticsearch 或 OpenSearch。

用于：

- 精确关键词；
    
- 型号；
    
- 编号；
    
- 人名；
    
- 合同条款；
    
- 日期；
    
- 专业术语。
    

### 知识图谱

可以使用 Neo4j 或 PostgreSQL 图模型。

用于表示：

```text
用户 → 负责 → 欧佐内项目
欧佐内项目 → 包含 → 水源厂
水源厂 → 包含 → 6号泵
6号泵 → 发生 → 异响
异响 → 可能由 → 轴承磨损
```

### 原始资料存储

使用对象存储或文件系统保存：

- 全部对话原文；
    
- PDF；
    
- 图片；
    
- 音频；
    
- 视频；
    
- 表格；
    
- 工程资料；
    
- 工具执行日志。
    

## 7.2 推荐组合

初期原型可以采用：

```text
PostgreSQL
+ pgvector
+ 文件存储
+ Redis
```

较成熟阶段可以采用：

```text
PostgreSQL
+ Qdrant
+ Elasticsearch
+ Neo4j
+ MinIO
+ Redis
```

# 八、记忆写入机制

不能把每一句对话都直接写成长期记忆。

需要经过记忆筛选。

## 8.1 记忆重要性评分

可设计评分公式：

[  
S =  
w_1I +  
w_2R +  
w_3E +  
w_4N +  
w_5F +  
w_6C  
]

其中：

- (I)：重要程度；
    
- (R)：与长期目标的相关性；
    
- (E)：情绪强度；
    
- (N)：信息新颖性；
    
- (F)：未来复用概率；
    
- (C)：可信度。
    

示例权重：

```text
重要程度：30%
目标相关性：25%
未来复用概率：20%
可信度：15%
新颖性：5%
情绪强度：5%
```

## 8.2 记忆等级

### 一级：核心记忆

长期保留：

- 用户明确要求记住；
    
- 关键身份信息；
    
- 重大决策；
    
- 重要项目参数；
    
- 安全相关内容；
    
- 长期目标。
    

### 二级：重要记忆

保存较长时间：

- 当前项目状态；
    
- 重要任务结果；
    
- 典型经验；
    
- 反复使用的信息。
    

### 三级：普通记忆

保存原始记录，但默认检索权重较低。

### 四级：临时记忆

只在当前任务或短期内使用。

# 九、记忆检索机制

## 9.1 混合检索

检索得分建议综合：

[  
Score =  
\alpha S_v +  
\beta S_k +  
\gamma S_t +  
\delta S_g +  
\epsilon S_i +  
\zeta S_c  
]

其中：

- (S_v)：向量语义相似度；
    
- (S_k)：关键词匹配；
    
- (S_t)：时间相关性；
    
- (S_g)：目标相关性；
    
- (S_i)：记忆重要性；
    
- (S_c)：上下文一致性。
    

## 9.2 检索流程

```text
理解当前问题
↓
识别人物、项目、时间和实体
↓
生成多个检索子问题
↓
执行向量检索
↓
执行关键词检索
↓
执行图谱查询
↓
合并和去重
↓
冲突检测
↓
重新排序
↓
装入工作空间
```

## 9.3 多轮检索

复杂问题不应只检索一次。

例如：

```text
第一轮：搜索项目背景
第二轮：搜索设备参数
第三轮：搜索过去类似故障
第四轮：搜索已做过的决策
第五轮：验证当前结论是否冲突
```

# 十、记忆冲突与版本控制

长期智能体一定会遇到信息冲突。

例如：

```text
旧记忆：设备计划4月到场
新记忆：设备延迟到5月到场
```

系统不能简单删除旧信息，也不能平等使用两条信息。

建议采用：

```json
{
  "fact": "设备到场日期",
  "versions": [
    {
      "value": "2026-04",
      "status": "superseded"
    },
    {
      "value": "2026-05",
      "status": "current"
    }
  ]
}
```

每条记忆建议包含：

- 创建时间；
    
- 更新时间；
    
- 来源；
    
- 当前状态；
    
- 置信度；
    
- 有效时间；
    
- 替代关系；
    
- 是否已被确认。

# 十一、记忆巩固机制

记忆巩固相当于人类睡眠期间的信息整理。

智能体应定期执行：

1. 汇总当天或当前阶段的事件；
    
2. 合并重复信息；
    
3. 提取稳定事实；
    
4. 提取可复用经验；
    
5. 更新人物和项目状态；
    
6. 生成阶段摘要；
    
7. 发现矛盾；
    
8. 降低无关记忆权重；
    
9. 将高频步骤转化为技能；
    
10. 保留重要原始证据。
    

## 11.1 日级巩固

每天处理：

- 当日对话；
    
- 新增事件；
    
- 新增任务；
    
- 用户反馈；
    
- 错误和修正。
    

## 11.2 项目级巩固

项目达到关键节点时，生成：

- 项目摘要；
    
- 决策清单；
    
- 风险清单；
    
- 未完成事项；
    
- 经验教训；
    
- 关键数据快照。
    

## 11.3 长期知识抽象

多次类似事件可以提炼成一般知识。

```text
多个单独故障案例
↓
识别共同模式
↓
形成故障诊断规则
↓
更新程序性记忆
```

# 十二、遗忘机制

遗忘不等于删除。

系统可以降低某条记忆的激活概率。

## 12.1 记忆强度

[  
M_t =  
M_0  
\times  
e^{-\lambda t}  
\times  
(1+r)  
\times  
(1+i)  
]

其中：

- (M_0)：初始记忆强度；
    
- (t)：未使用时间；
    
- (\lambda)：衰减率；
    
- (r)：重复使用强化；
    
- (i)：重要性强化。
    

## 12.2 不应遗忘的内容

- 用户明确要求长期记住的信息；
    
- 安全规则；
    
- 核心身份；
    
- 核心价值；
    
- 重大决策；
    
- 合同与法律依据；
    
- 关键设备参数；
    
- 已确认的错误纠正。
    

## 12.3 可弱化内容

- 一次性闲聊；
    
- 临时计算过程；
    
- 重复内容；
    
- 被新版本替代的信息；
    
- 与长期目标无关的细节。

# 十三、目标系统

## 13.1 目标分层

建议设置四层目标：

### 核心目标

长期不轻易改变，例如：

- 帮助用户完成任务；
    
- 保证结果可信；
    
- 避免造成伤害；
    
- 维护长期合作关系。
    

### 长期目标

例如：

- 建立用户的工程知识体系；
    
- 协助完成某个大型项目；
    
- 建立个人智能助手。
    

### 项目目标

例如：

- 完成欧佐内项目缺陷整改；
    
- 完成人脑式智能体原型。
    

### 当前任务目标

例如：

- 输出架构文档；
    
- 检查代码；
    
- 生成实施方案。

# 十七、推理与规划引擎

推理层不应只进行一次性回答。

建议提供多种思考模式。

## 17.1 快速模式

适合：

- 简单事实；
    
- 简单解释；
    
- 普通翻译；
    
- 简短写作。
    

流程：

```text
理解 → 检索少量记忆 → 回答
```

## 17.2 标准模式

适合：

- 技术分析；
    
- 方案设计；
    
- 项目问题。
    

流程：

```text
理解
→ 分解问题
→ 检索
→ 建立方案
→ 验证
→ 输出
```

## 17.3 深度模式

适合：

- 复杂研究；
    
- 多因素决策；
    
- 长期规划；
    
- 高风险任务。
    

流程：

```text
任务分解
→ 多轮检索
→ 多假设生成
→ 证据比较
→ 工具验证
→ 反方审查
→ 风险评估
→ 结论生成
```

## 17.4 多代理模式

可以设置不同角色：

- 规划代理；
    
- 记忆代理；
    
- 研究代理；
    
- 批判代理；
    
- 执行代理；
    
- 审核代理。
    

主智能体负责整合结果。

# 十八、元认知系统

元认知是智能体判断自己思考质量的能力。

## 18.1 元认知问题

智能体应定期询问自身：

- 我是否真正理解了当前任务？
    
- 当前证据是否充分？
    
- 是否遗漏了关键记忆？
    
- 是否存在冲突信息？
    
- 当前答案是事实还是推测？
    
- 是否需要调用工具？
    
- 是否重复推理但没有进展？
    
- 是否已经达到停止条件？
    
- 是否应该向用户说明不确定性？
    

## 18.2 置信度分级

```text
高置信度：有明确数据和多个一致来源
中置信度：有一定依据，但存在缺失
低置信度：主要依赖推断
未知：没有足够信息
```

## 18.3 反思触发条件

当出现以下情况时触发反思：

- 用户指出错误；
    
- 两个来源冲突；
    
- 结论影响较大；
    
- 工具结果异常；
    
- 连续多次行动失败；
    
- 置信度过低；
    
- 推理过程过长；
    
- 结果与常识明显冲突。

# 二十七、单轮运行伪代码

```python
def cognitive_cycle(user_input):
    event = perception.parse(user_input)

    current_goal = goal_manager.identify_goal(event)

    recent_context = memory.get_recent_conversation()

    related_memories = memory.retrieve(
        query=event.content,
        goal=current_goal,
        entities=event.entities
    )

    workspace = workspace_manager.build(
        event=event,
        goal=current_goal,
        recent_context=recent_context,
        memories=related_memories
    )

    plan = cognitive_controller.decide(workspace)

    result = reasoning_engine.execute(plan, workspace)

    evaluation = metacognition.evaluate(
        result=result,
        workspace=workspace
    )

    if evaluation.need_more_memory:
        extra_memories = memory.retrieve(
            query=evaluation.missing_information
        )
        workspace.add(extra_memories)
        result = reasoning_engine.execute(plan, workspace)

    response = action_manager.respond(result)

    new_memories = memory_writer.extract(
        event=event,
        response=response,
        result=result
    )

    memory_writer.save(new_memories)

    goal_manager.update(result)

    return response
```

# 二十八、系统设计原则

## 原则一：上下文不是记忆库

上下文只应保存当前思考需要的信息。

## 原则二：原始记录与提炼知识分离

原始记录负责追溯，提炼知识负责高效使用。

## 原则三：记忆必须有来源

每条重要事实都应知道来自哪里。

## 原则四：新信息不能直接覆盖旧信息

应通过版本控制和有效状态处理。

## 原则五：检索应由当前目标驱动

不能只按文本相似度搜索。

## 原则六：智能体必须知道自己的不确定性

不能把推测当作事实写入长期记忆。

## 原则七：长期人格来源于稳定状态

人格不应只依靠一段系统提示词，而应由价值、经历、自我模型和长期目标共同维持。

## 原则八：记忆写入比记忆读取更重要

错误记忆一旦反复使用，会形成持续性错误。

## 原则九：高风险行动必须受控

智能体自主性越高，权限控制越重要。

## 原则十：先建立可靠记忆，再追求自主意识

没有可靠记忆的自主智能体，只会持续积累混乱。

# 二十九、最终模型公式

整个人脑式智能体可以抽象为：

[  
A_t =  
F(  
W_t,  
M_t,  
G_t,  
S_t,  
V_t,  
E_t,  
X_t  
)  
]

其中：

- (A_t)：当前行动；
    
- (W_t)：工作空间；
    
- (M_t)：被激活的长期记忆；
    
- (G_t)：当前目标；
    
- (S_t)：自我模型；
    
- (V_t)：价值系统；
    
- (E_t)：环境状态；
    
- (X_t)：工具与外部能力。
    

行动完成后：

# [  
M_{t+1}

Update(M_t, E_t, A_t, Feedback_t)  
]

因此，这个智能体不是一个静态模型，而是一个持续运行的认知系统。

# 三十、最终建议

第一版最值得投入的不是情绪模拟，也不是超长上下文，而是以下五项：

1. 高质量的结构化长期记忆；
    
2. 准确的混合检索；
    
3. 清晰的目标和任务状态；
    
4. 可靠的记忆更新与冲突管理；
    
5. 可循环执行的认知控制器。
    

只要这五项实现得足够稳定，即使主模型只有 128K 上下文，也可以表现出明显的长期连续性。

项目的核心路线应是：

```text
长期记忆
→ 动态检索
→ 工作空间
→ 推理行动
→ 结果反馈
→ 记忆更新
→ 经验巩固
```

最终目标不是制造一个拥有无限上下文的大模型，而是建立一个能够持续经历、持续记忆、持续思考和持续修正的认知智能体。
