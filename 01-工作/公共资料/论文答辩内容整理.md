## 问题1我选题的原因是什么

**核心逻辑：从宏观背景 $\rightarrow$ 现状缺陷 $\rightarrow$ 技术方案选型 $\rightarrow$ 预期目标**

“关于选题原因，我主要从以下四个维度进行了思考：

**1. 宏观背景与紧迫性：**
工业领域是能耗大户，我国工业能源消耗占比极高。随着能源成本上升和环保政策加强，企业如果不能精准掌控能耗，将直接影响生产成本和竞争力。因此，开发一套高效的能耗监测系统具有很强的现实意义。

**2. 现有监测手段的不足：**
在调研中我发现，目前很多企业处于‘能耗黑盒’状态。一方面是**采集手段落后**，依赖人工，导致数据更新慢，无法及时发现能耗异常；另一方面是**分析能力薄弱**，即便有数据，也只是简单的数值记录，缺乏对设备运行效率（如负载率）和电费成本（如峰谷平）的深度挖掘。

**3. 技术方案的针对性选型：**
我对比了市面上的高端MES系统（成本太高，不适合中小企业）和传统的SCADA组态软件（灵活性差，难以做深度数据分析）。因此，我选定了‘**S7-1200/1500 PLC + WinForm + MySQL**’这个架构。PLC保证了工业级的稳定采集，MySQL解决了海量数据的存储，而WinForm则提供了高度灵活的自定义分析界面，旨在为企业提供一个‘高性能且低成本’的解决方案。

**4. 预期的实践价值：**
我希望通过这个系统，实现从‘被动记录’到‘主动管理’的转变。通过负载率分析判断设备是否大材小用，通过峰谷平分析优化生产排班，通过线性回归预测未来能耗，为企业的数字化转型提供技术支撑。”

## 问题2 全文的基本框架是如何安排的

**核心逻辑：从底层硬件到顶层应用，从数据采集到价值挖掘。**

“本论文的框架是按照**‘由底向上’**的工程实现逻辑来安排的，具体分为四个阶段：

第一阶段是**理论准备与需求分析**（第1-2章）。首先分析工业能耗监测的背景，明确系统需要实现的功能（采集、存储、分析、显示），并确定‘PLC+WinForm+MySQL’的整体架构。

第二阶段是**硬件与数据链路的搭建**（第3-4章）。这是系统的底层，重点阐述如何通过PLC采集电流电压信号，以及如何利用工业以太网将数据可靠地传输到上位机。

第三阶段是**软件平台与数据管理实现**（第5-6章）。这是系统的中层，重点介绍基于WinForm的监控界面开发以及MySQL数据库的存储优化，解决了数据的‘怎么存’和‘怎么看’的问题。

第四阶段是**数据分析与系统验证**（第7-8章）。这是系统的顶层，通过负载率、峰谷平、趋势预测三大算法将原始数据转化为能耗分析结论，并通过实验室环境的测试验证系统的精度和稳定性。

最后，在第9章对研究结论进行总结并展望未来的优化方向。”

## 问题3 论文和系统有哪些不足

**正确的回答策略是：承认局限性 → 给出专业分析 → 提出改进方向。**

### 1. 关于分析算法的局限性（学术深度维度）

**不足点：** 预测算法较为简单。 
**怎么说：** “在能耗趋势预测方面，目前系统采用的是**线性回归算法**。这种算法在处理具有明显线性趋势的数据时效果较好，但工业现场的能耗数据往往受到生产计划、季节波动和随机干扰的影响，呈现出复杂的非线性特征。因此，线性模型在预测长期趋势时的精度有所不足。” 
**改进方向：** “在未来的优化中，我计划引入更深层的**机器学习算法**，引入AI大模型，以捕捉数据中的非线性模式，提高预测的准确率。”

### 2. 关于软件平台的扩展性（实用场景维度）

**不足点：** 仅支持桌面端，缺乏远程访问能力。
**怎么说：** “目前上位机软件基于 **WinForm 框架**开发，属于典型的桌面应用程序。这意味着用户必须在安装了软件的特定计算机上才能查看数据，无法实现跨平台的远程监控，在实际工业场景中，管理人员可能需要随时随地通过手机或平板查看能耗状态，目前的系统在便捷性上有所欠缺。” 
**改进方向：** “未来的迭代方向是将后端 API 化，开发移动端 App，实现基于云端的远程能耗管理。”

### 3. 关于系统规模与架构（工程部署维度）

**不足点：** 采用单机集中式架构，扩展压力大。
**怎么说：** “目前的系统架构是‘PLC → 单台上位机 →单个 MySQL 数据库’。在实验室小规模测试环境下运行稳定，但如果未来推广到整个工厂，面对成百上千台设备的实时海量数据写入，单点数据库可能会出现 I/O 瓶颈，且缺乏高可用性的冗余备份机制。”
**改进方向：** “可以引入**边缘计算（Edge Computing）**的概念，在现场部署边缘网关进行初步的数据清洗和聚合，减轻云端/中心数据库的压力，并采用分布式数据库集群来提升系统的稳定性。”

### 4. 关于测试环境的真实度（验证环节维度）

**不足点：** 实验环境与真实工业现场存在差异。
**怎么说：** “本系统的测试主要是在实验室环境下完成的，负载设备相对单一，且电磁干扰环境较为纯净。而真实的工业现场存在复杂的强电干扰、极端温度以及不稳定的网络环境，系统在极端情况下的鲁棒性（抗干扰能力）还需要在实际生产线中进一步验证和打磨。” 
**改进方向：** “下一步计划将系统部署到实际的生产车间进行试点运行，重点测试在强电磁干扰环境下数据的丢包率和信号稳定性，并据此优化硬件滤波电路和通信重传机制。”
